# Initial community interoperability trials — 2026-11-13

Host: Open-test, Ubuntu 24.04.4 x86_64, Python 3.12. Released iaiops 0.34.0 from
the existing isolated lab venv, with paho-mqtt 2.2.0. This was software simulation
on loopback interfaces; no physical OT device or control write was involved.

## eKuiper

- Official LF Edge eKuiper **2.4.2**, Linux amd64 core release archive SHA-256
  `aed464dc2ef332dabba0b499bca264015d44d25facd77134db4d673d9a0fc522`,
  matched the upstream `.sha256` asset.
- Real Mosquitto broker image
  `public.ecr.aws/docker/library/eclipse-mosquitto@sha256:75d6662dee52c947dc9dd9c29f1d8d7ffef78ddaf38001caa09755681e8bbc98`.
  Anonymous access confined to host loopback port 18883; no published OT port.
- eKuiper CLI/REST listeners were explicitly bound to loopback; REST reported
  version 2.4.2. The MQTT source and result sink pointed at the local broker.
- `demo/ekuiper/verify_live.py` called the installed **governed** `uns_publish`
  using isolated temporary audit state. Five simulated input points produced
  four numeric publications and one nonnumeric skip. The quality rule excluded
  999/bad and observed one window with count 3 and mean 20 for values 10/20/30.
- `omitIfEmpty` suppressed empty-window messages; no later numeric observation
  appeared during publisher silence. Rule and stream were removed after the run.
- Raw observed result: [ekuiper-result.json](ekuiper-result.json), SHA-256
  `8056543bad3dab7414b8260622da25b99353e9d282a04004932da74e4ed591f4`.

Limit: processing-time windows only; no event-time watermark, late/out-of-order
case, reconnect, broker TLS, physical meter or production egress test. Input
quality is an explicit fixture declaration and not inferred from plant context.

## Eclipse Tahu encoder → iaiops decoder

- Unmodified Tahu master source pinned at
  `5736e404889d4b95910613040a99ba79589ffb13`.
- Tahu's own Python API/protobuf encoded the fixture in a separate subprocess;
  the installed iaiops decoder received the bytes through a real MQTT subscription.
  The pure-Python protobuf compatibility setting was confined to the encoder.
- Six checks passed: NBIRTH named metric, epoch-millisecond timestamp, alias-only
  NDATA, NDEATH refusal of cached data, NBIRTH replacement/removal, stale refusal.
- Raw observed result: [tahu-result.json](tahu-result.json), SHA-256
  `2bf1f5787a04dcdca058da6fac10759c08bacc73e67bdd24a45e382806c37517`.

Limit: the sender/state-machine harness is ours. This is independent encoder
interoperability, not a third-party EoN lifecycle implementation, TCK run or
Sparkplug Compatible certification. The fixture supplies explicit source timestamps.

## Separate upstream finding

Review of the Tahu helper found `addMetric`'s omitted timestamp evaluated once at
module import. On upstream `develop` `c19db8c`, two of three regression tests
failed; moving default evaluation to call time made all three pass, preserving
explicit timestamps including zero. Submitted separately to
[eclipse-tahu/tahu#472](https://github.com/eclipse-tahu/tahu/pull/472).
The interoperability trial above used unmodified master and is not a test of
that patch. Upstream acceptance and Eclipse contributor agreement checks remain
separate from the local test result.
